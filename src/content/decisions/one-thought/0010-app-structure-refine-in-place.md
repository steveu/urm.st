Before real counting was built, the app's structure was put on trial. With only about 1,750 lines written, a rewrite would have been cheap, so the question was asked properly rather than answered by inertia. On 3 July a nine-agent panel assessed the app: three independent assessors, three competing structure proposals argued from assigned stances, and three judges scoring proportionality, iOS idiom and fit with the plan.

The panel's read of the code: the bones were right. SwiftUI's `.environment` injection is current practice, and the custom router was *justified*, not legacy, because `NavigationStack` can't host the app's book-style page turn (220ms in, 150ms out — [“The design-system specimen is the paper register’s authority”](./adopt-design-system-specimen)'s motion table). But everything testable was untestable. The store hardwired its on-disk database path and crashed on launch failure. There was no unit-test target. Four error-handling regimes coexisted — crashing, `do/catch`, silently swallowed errors, and unhandled throws. The acceptance walk slept a fixed 3.5 seconds and counted strings across the whole page. And the device's language sat inside the domain: a simulated click lived on the store, when the glossary demands that a button *press* is translated into a *tap* at the boundary — "the domain never says press".

The decision: **refine in place.** One app target, folders rather than modules, generated by XcodeGen as before. The store facade and the custom router stay, hardened rather than replaced:

- The store gets a designated initialiser that takes a database queue (the on-disk path moves to a convenience initialiser), and every read and write goes through two helpers that own logging and fallback, ending the four error regimes. A failed launch shows a "book closed" screen instead of crashing. The book is never deleted.
- **An in-memory database is the only test seam.** No repository protocols, no mocks — a unit-test target runs the real store against a real in-memory database.
- The router keeps a **trail** — push, pop, replace — so back-targets stop being hardcoded per screen.
- The Device context lands as a folder, not a framework: a button service with a single funnel for presses, calling the store's domain verbs — record a tap, mark a moment — in place of the old "simulate" names. Later, a Flic adapter exposes the Flic library as an async stream, compiled out of the simulator.
- A roughly 40-line wrapper over GRDB's `ValueObservation` is used **only where a screen outlives its data**. The home screen keeps pulling its data; observation everywhere was explicitly rejected.
- The per-tap GPS fix type is deliberately **not** `Codable`, so accidentally exporting a fix fails to compile. Nothing in the location code may import a networking module — [“OpenStreetMap architecture: hosted course catalogue, matching on the phone”](./osm-architecture-hosted-geometry)'s privacy tripwire, enforced by structure.
- Concurrency is staged: the store and router go `@MainActor` with strict concurrency checking under Swift 5 first, and the Swift 6 flip waits for zero warnings. Codable record types wait for the next schema version rather than being converted speculatively.

It landed as **eleven pre-work commits before real counting**, each leaving the acceptance walk green: harden the walk itself (no fixed sleeps, assertions scoped to rows); cut the menu to the documented six ([“The menu seeds only documented thoughts”](./documented-thoughts-only)); the error-policy pass and the "book closed" screen; the unit-test target; extract migrations and seed data; main-actor isolation and strict concurrency; the domain verbs; the router trail; the observation wrapper; CI; and the button funnel. That shrank the Flic integration to an adapter behind an interface that already existed.

## Consequences

- The plan's "architecture held constant" paragraph is ratified and now has teeth: the shape it holds constant is tested, not just asserted.
- Real counting starts from a Device seam that already exists; the simulator's controls become the first client of the same funnel the Flic will use.
- The acceptance walk stays the gate for every structural commit. A step that can't land green is reverted, not accommodated.

## Considered and rejected

- **Bounded contexts as Swift packages**, one per glossary context. Rejected unanimously. At this size it buys around 30 `public` keywords and a gamble on shipping the Flic library as a binary framework inside a package, and it slows every build. The glossary's contexts are honoured as folders and types instead.
- **A Swift-6-first, observation-everywhere rebuild.** Rejected. It re-platforms working code the panel judged idiomatic, throws away a green acceptance walk, and buys nothing the next two milestones need; strict concurrency arrives staged instead.
- **Async domain writes.** Rejected. The writes are tiny, synchronous database transactions on the main actor, and async signatures would smear ceremony timing through every screen.
- **`NavigationStack`.** Rejected on a hard constraint: it can't host the page-turn transition.
- **TCA or another architecture framework.** Rejected. The app's whole state is one facade and five screens; a framework would be structure for structure's sake.
